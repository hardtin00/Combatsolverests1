# Combat Solver 1

面向《杀戮尖塔》（Slay the Spire 1）的战斗路线求解器 Mod，功能对齐
[Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver)（该项目的目标平台是
《杀戮尖塔 2》，C# / .NET / Godot 技术栈）。

一代是 Java + ModTheSpire + BaseMod 的完全不同的 Mod 体系，因此本项目是**功能对等的全新实现**，
不是对 CombatSolver 的代码移植。当前工作版本为 **0.3.1（未发布）**；`v0.3.0` 是此前源码标签，精度仍需真实游戏记录持续验证。

### 实机捕获的状态范围

模拟根会从实机读取：生命 / 格挡 / 能量 / 手牌 / 抽牌堆（含顺序）/ 弃牌堆 / 消耗堆 /
遗物 / 药水 / 进阶等级 / 回合数；怪物的生命 / 格挡 / 力量 / 易伤 / 虚弱 / 当前意图 /
招式游标；以及**玩家侧**的虚弱 / 残废 / 缠身 / 无形 / 神器 / 板甲 / 缠绕与全部能力牌层数。

洗牌与随机招式仍使用模拟器内置 RNG（**未复制游戏真实 RNG 序列**），这是已知的精度边界；
因此路线会附上"4 个随机分支下的扣血区间与是否均能取胜"，用区间表达不确定性取代表面上的确定性。
搜索内部会区分不同的模拟 RNG 游标；这只避免搜索把不同模拟分支错误合并，**不代表模拟 RNG 与游戏 RNG 一致**。

## 架构（对标 CombatSolver）

与原项目一致的“预测优先”运行链：

1. 回合开始时，在主线程捕获一份稳定的战斗根状态（只读，不改动真实战斗）。
2. 在独立的分支状态上做**整场战斗**的 Beam Search：推演“本回合怎么打 → 结束回合 →
   怪物行动 → 抽新牌”，逐回合展开，直到分出胜负或用完预算。
3. 搜索结束后产出一条完整的只读路线（预测）；面板展示逐回合出牌与预计剩余生命。
4. **默认只预测不执行**：只有你按键时，才用游戏原生入口把路线中的“当前回合”部署到实机。

代码结构：

```text
engine/    纯模拟：可 fork 的战斗状态、卡牌效果模板、结算规则（不引用游戏对象）
search/    整场 Beam Search 与只读路线（Plan）
runtime/   实机桥接：捕获战斗根、部署当前回合、控制器
ui/        只读路线面板
```

## 已实现

- 整场战斗的预测搜索（Beam Search），输出逐回合路线、预计承伤、是否可击败。
- 卡牌效果建模：铁甲 75 张全部登记，伤害 / 格挡 / AOE / 易伤 / 虚弱 / 力量 / 过牌 / 能量 /
  消耗联动 / 牌库操作（复制、取回、生成、洗入状态牌）。选牌类卡牌（双持 / 头槌 / 掘墓 /
  燃烧契约 / 军备）按价值选最适合的目标，只有 2 张仍标近似。
- 怪物行动：**65 只原版怪物均有招式 / AI 模型**，并按进阶等级使用相应数值或脚本；招式选择参考
  Bestiary（MIT）的 AI 数据并经字节码交叉核对。仪式、睡眠与打醒、狂怒、蓄力、模式切换、
  飞行与击落、召唤、复活、逃跑及多阶段等特殊机制按模型支持；但个别怪物的复杂阶段 / 条件分支
  仍有近似，具体边界以支持矩阵、`MonsterManual` 注释和差分测试为准。第三方来源与署名见
  [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
- 牌堆语义与游戏一致：抽牌从牌堆顶取、洗牌整堆 Fisher–Yates、实机捕捉到的牌堆顺序直接沿用。
- 玩家侧减益真实生效：虚弱（伤害 −25%）、残废（格挡 −25%）、缠身（不能打攻击牌）。
- 遗物触发：钢笔尖 / 红骷髅 / 冰淇淋 / 水银沙漏 / 山铜护符 / 羊角扣 / 船长轮盘 / 青铜鳞片 /
  手里剑 / 苦无 / 双节棍 / 开信刀 / 卡戎之灰。
- **差分验证脚手架**：实机每次出牌与回合切换都会写结构化记录（JSONL），离线工具
  （`tools/solvertest`）把记录重放回模拟器并逐字段比对；CI 每次提交都会跑数据表、
  怪物行动、搜索与差分重放四组断言。
- 会识别击杀并把攻击分配到合适目标，避免溢出伤害。
- 右上角面板展示完整预测路线（逐回合出牌与预计剩余生命）。

### 可视化窗口

战斗中出现一个可拖动窗口（拖标题栏移动），展示整场预测路线：

- **状态区**：标题栏带状态点；状态徽章（等待 / 搜索中 / 就绪 / 执行中 / 已暂停）
  + 摘要主行（预计整场扣血、剩余生命）+ 搜索进度条；
- **路线区**：逐回合行（当前回合金色高亮，后续回合变暗），每回合一行：
  回合号 T1/T2…、彩色行动胶囊（攻击红 / 技能蓝 / 能力金 / 药水青 / 选牌橙 /
  结束回合灰）、右侧“受击 / HP / 能量”三项指标；超过 5 回合可展开完整路线；
- **底部操作栏**（与内容区有分隔线）：全自动、**执行本回合**（金色主按钮）、
  重新计算（搜索中变“停止搜索”）、暂停。

窗口右上角提供三个设置（点击切换，设置会保存到用户目录
`~/.combatsolver1/settings.properties`；路线超过 5 回合时可点“展开全部”查看完整路线）：

| 设置 | 取值 |
| --- | --- |
| 搜索预算 | 低 / 中 / 高 / 极高 / 自定义（映射到 Beam 宽度、回合上限与节点上限） |
| 面板透明度 | 55% / 75% / 100%（面板底色保底 88% 不透明，保证文字可读） |
| 主题 | 深色 / 浅色 |

### 快捷键（与按钮等效）

| 按键 | 作用 |
| --- | --- |
| 不按键 | 仅查看路线：只预测并展示，不执行 |
| `G` | 执行本回合：只把牌打完，不结束回合 |
| `H` | 全自动：开关连续执行，打完牌后自动结束回合 |
| `J` | 停止 / 暂停：立即停止当前搜索，并暂停本场后续自动预测与执行 |
| `R` | 重新计算：解除暂停并重新预测 |

搜索是增量推进的，不会卡帧，也可以在搜索过程中随时用 `J` 中断。

### 跨回合搜索与路线复用

- 搜索会一直推演到分出胜负或用完预算，包含抽牌、洗牌、敌人行动与后续资源。
- 评估顺序为“生存 > 确认胜利 > 整场生命损失”。
- 每个回合会先核对已捕获的实机状态与预测是否一致：一致则可能**复用既有路线**，不一致才重新搜索；此核对不覆盖游戏真实 RNG 和所有隐藏触发计数，涉及洗牌 / 随机 AI 的未来路线仍可能偏离。

## 当前明确的限制

- **实机闭环尚未验证**：CI 与离线断言不等于游戏内实测；请用真实 JSONL 记录运行 `diff`，并反馈失败记录。
- 洗牌 / 随机招式未复制游戏真实 RNG；4 分支复推只是有限抽样，不是概率保证或穷举证明。
- 随机生成牌、蛇眼费用随机化、处刑者伤害段数及少数选牌类仍为近似；职业限制、未建模卡牌 / 怪物也会降低路线可信度。
- 其他职业牌池与机制、逐瓶药水策略 UI、局外成长策略、战前预测 API、问题反馈与在线统计尚未实现。
- 发布前仍需在安装了《杀戮尖塔》及 ModTheSpire / BaseMod 的机器上构建，并完成启动和战斗中的人工验收。

详见 [ROADMAP.md](ROADMAP.md)。

## 差分验证与离线自检

```powershell
powershell -ExecutionPolicy Bypass -File tools/solvertest/run.ps1            # 全部自检
powershell -ExecutionPolicy Bypass -File tools/solvertest/run.ps1 -Command diff `
  -RecordFile "$env:USERPROFILE\.combatsolver1\recordings\combat-20261016-120000.jsonl"
```

自检**不需要游戏本体**：只编译 `engine` 与 `search` 两个纯模拟包。CI 配置见
`.github/workflows/ci.yml`。实机记录落在 `~/.combatsolver1/recordings/`，
每条动作比对生命 / 格挡 / 能量 / 玩家减益与已建模能力 / 手牌 / 牌堆数量及牌身份 / 每个怪物的血量、格挡、状态与防御能力。新增字段仅在相应记录包含时才可校验；旧记录按零值解释。
详细说明见 [tools/solvertest/README.md](tools/solvertest/README.md)。

## 构建

**完整 Mod 构建（推荐）**：在装有游戏的机器上运行

```powershell
powershell -ExecutionPolicy Bypass -File tools/build/build-release.ps1          # 只编译打包
powershell -ExecutionPolicy Bypass -File tools/build/build-release.ps1 -Deploy  # 顺带装进 mods/
```

脚本会自动找游戏目录与创意工坊里的 ModTheSpire / BaseMod，编译、打包，并输出
**版本号、commit SHA、jar 的 SHA-256**（同时写到 `build/libs/release-info.txt`）。
对外发布时请以这份产物的 commit 为准——仓库**不再**存放 jar，避免下载者拿到过期版本。

注意：GitHub Actions 只跑不依赖游戏文件的离线自检；CI 里的"完整 Mod 构建"在仓库没有
`libs/` 时会**明确标记为未执行**（会在运行摘要里写明），不会把"跳过的构建"算成通过。

前置条件：

- JDK 8 或更高版本
- Gradle 7.x（或使用你的 IDE 自带的 Gradle）
- 《杀戮尖塔》安装目录，其中包含 `desktop-1.0.jar`、`ModTheSpire.jar` 与
  `mods/BaseMod.jar`

执行（把路径替换成你的实际安装目录）：

```powershell
gradlew jar -PstsDir="C:/Program Files (x86)/Steam/steamapps/common/SlayTheSpire"
```

或者设置环境变量 `STS_DIR` 后直接 `gradlew jar`。产物为
`build/libs/CombatSolver1.jar`。

## 安装与使用

1. 把 `CombatSolver1.jar` 放入游戏目录的 `mods/` 文件夹。
2. 用 ModTheSpire 启动游戏，勾选 `BaseMod` 与 `Combat Solver 1`。
3. 进入一场单人战斗，发牌结束后右上角即显示建议面板。
4. 按 `G` 执行当前建议路线；按 `H` 开启 / 关闭全自动。
