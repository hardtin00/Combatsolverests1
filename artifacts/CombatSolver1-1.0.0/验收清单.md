# 第五轮：找到并修复真正的根因（2026-11-06 06:25）

用户 06:04「还是没有反应，路线求解也不对了」。

**根因**：上一轮 ASM 把 `ifne` 改成 `goto` 破坏了 JVM 栈图，游戏执行采集方法时抛
`java.lang.VerifyError: Inconsistent stackmap frames`。采集层整个崩掉 → 不写状态文件 →
引擎不运行 → 没有搜索结果 → 面板显示兜底乱码、按钮点了像没反应、战损/路线全不对。
`-Xverify:all` 只做类加载冒烟测试，不执行方法，所以一直没暴露。

**诊断手段**：新增 `diag()` 每 2 秒把 state / problem / screen / room / plan / drive 写进
`panel-layout.log`，一眼定位到 `problem=E-INTERNAL java.lang.VerifyError ...`。

**修法**：`RelaxFullUuid2` 保留原控制流，只在 `ifne` 前插 `pop; iconst_1`，栈高不变、
栈图不变，合法重复 uuid 不再致命。

**真机验证（r23，用户 06:02 存档）**：

| 项 | 证据 |
|---|---|
| VerifyError 消失 | `diag state=IDLE problem=` 干净 |
| 求解真的跑起来 | `SEARCH_RESULT.live1.json` `SEARCHED PLAYER_VICTORY terminal_turn=5` |
| 整场计划 | `diag plan=16`、面板 `▶ Full fight plan (16 steps / 5 turns)`、Turn 1–4 分组 |
